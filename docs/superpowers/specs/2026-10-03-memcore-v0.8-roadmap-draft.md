### The one number that matters

```
journal: health=operator_attention, events=340,
         semantic_pending=11, unresolved_builtin=2, failed=0
analysis: total=269 → ignore 223 (83%) / remember 30 (11%) / defer 16 (6%)
corroborate --project shared-platform --agent mika  →  0 multi-source claim(s)
decay   → 0    journal-sweep → 0
```

**Read:** the pipeline is not idle — it is *productive and useless*. 269 analyzer runs, 83% "ignore", 0 claims that ever reached the corroboration threshold. Backlog is 13 pending, oldest ~8.5 days, and `corroborate` has never fired. The Golden Rule (ADR-0018), the headline autonomy feature of v0.7, has **zero real inputs**.

**Root cause (INFERENCE, needs SORA's audit to confirm):** corroboration counts DISTINCT `owner_agent_id`. `stats` shows mika=101, milim=2, pchoke=2, nua=1, sora=1 — and the deterministic gate classifies ordinary ambient turns as trivial. So no fingerprint is ever held by 3 agents. The feature is implemented and unreachable.

**Second cause (FACT):** `auto_resolve_defer_cap` (`memcore/ingest.py:989`) exists and sweeps at `>= 3` defers, but `journal-sweep` reports 0 — the 5 deferred events have 1–2 defers each. The cap works; it just never fires because the backlog is not being reviewed enough to accumulate defers.

## 2. Phase 0 — Close the manual loop (no new capability)

Goal: **nothing in MemCore should ever wait for a human to click.**

### P0-1 · Corroboration must have reachable inputs
Choose one, decided with P Choke:
- **(a)** Let deterministic durable signals from *different agents* converge on one claim (MIKA + NUA independently record the same project fact → 2 sources → path to 3). Requires the recall path to surface an existing fingerprint to the agent before it writes.
- **(b)** Count corroboration from *evidence* (a claim backed by 3 distinct `evidence` rows / verified sources), not from distinct writers.
- **(c)** Seed the fleet canon set through an explicit governed path so ≥3 agents hold each of the ~10 canonical facts.

Recommendation: **(a)** — it matches the ADR-0018 intent (independent sources) and needs no schema change. Cost: S in phase 0, M if it requires recall-side fingerprint hints.

### P0-2 · MIKA as autonomous curator
No UI, per owner decision. The operator loop becomes a scheduled MIKA action:
1. `python -m memcore journal-stats` → if `health != ok`, pull `journal-review-list`.
2. Decide each event via `memory_review_decide` (remember / ignore / defer) with a written rationale.
3. `journal-sweep --apply` for stale builtins + defer caps.
4. `corroborate --apply` for anything that reached threshold.
5. Report counts back to P Choke.

SORA's audit must first answer: is `memory_review_decide` safe for an unattended loop — does it have a dry-run, an idempotency guarantee, and a blast radius limit? `[PENDING]`

### P0-3 · Minimum viable observability (replaces the deleted dashboard)
Per owner: AI-only surface. Minimum set, to be confirmed against SORA's §8:
- `doctor` gains a **corroboration-health** check: how many fingerprints are at 1/2/3/4/5 distinct agents (the funnel that currently reads all-zeros).
- `doctor` gains a **journal-age** check: oldest pending in days (today it reports a count, not an age trend).
- `stats` gains **golden + auto-promoted counts per day** so autonomy is visible as a rising number.
- All three must be content-free (no memory text), matching current `journal-stats` discipline.

**Acceptance:** a week of MIKA curation leaves `health=ok` without P Choke opening anything.

## 3. Phase 1 — Capability by relaxing stdlib-only (CONTROVERSIAL — needs a decision)

**This phase deliberately breaks a constraint the project has held since the start.** Flagging it rather than burying it:

- ADR-0020-era design and the whole README pitch rest on "Stdlib only · Zero external services · Daemonless".
- Relaxing it to add embeddings means: an embedding dependency, an index to rebuild on migration, a network call on the write path, a new failure mode, and a daemon or a lazy-build step for backfill.
- **Available today (FACT):** the fleet gateway already serves `gemini-embedding-001`, verified 3072 dims (memory `mem-1df34d262019`). So no new vendor is needed — but MemCore would gain an outbound dependency on a network service for a store whose entire pitch is local-first.

Options for P Choke:
- **1-A Full hybrid:** vector index alongside FTS5, RRF fusion. Highest quality, highest cost, breaks stdlib-only.
- **1-B Hybrid without a new service:** embeddings computed once at write time and cached in a new column; retrieval stays local. Backfill is a one-shot CLI pass. Mid cost, no runtime network dependency.
- **1-C Keep lexical; invest in the gap instead:** improve Thai/Unicode matching (segmentation-aware FTS), synonym expansion at index time, and better ranking. Zero dependency change.

Recommendation: **1-C first, 1-B later.** Rationale: the recall gap that actually hurts this fleet is Thai and paraphrase, and both are reachable lexically. Vectors are the expensive answer to a problem lexical work may solve. `[PENDING]` NUA's capability matrix decides whether the field has moved past lexical.

### Also in scope regardless of 1-A/1-B/1-C
- **Ranking quality becomes measured.** `harness/test_recall_quality.py` exists but asserts a handful of Thai queries. Build a real query set (fleet canonical facts, including negations) with precision@k, tracked over time. Right now there is no number for "recall got better".

## 4. Phase 2 — Capabilities that do not exist yet

Ordered by value-to-this-fleet, not by impressiveness:

### P2-1 · Contradiction detection `[PENDING NUA]`
Detect stored claims that conflict (same subject, incompatible predicate). Today the only defense is `tombstone` + `supersede`, both **reactive** — a human or agent must notice. No system in our stack notices a contradiction on its own.
Why it matters here: we are about to let an LLM auto-accept claims at confidence ≥ 0.95. Auto-accept without contradiction detection means confidently-wrong memories compound.
Cost: **L**. Needs a claim-subject extractor and a comparison rule; the engine must stay the authority (propose a conflict, never auto-resolve).

### P2-2 · Forgetting as reinforcement, not a date threshold `[PENDING NUA]`
`apply_freshness_decay(aging_days=30, stale_days=90)` is a pure clock — a fact written once is stale after 90 days whether or not it is true, load-bearing, or still true today. Real decay needs access counters (was this ever recalled? did recalling it help?) so that **used** facts reinforce and **never-recalled** facts fade.
Cost: **M**. Add access tracking on the recall path + a reinforcement term in the decay sweep.

### P2-3 · Consolidation / offline reorganization `[PENDING NUA]`
No "dreaming" pass exists. 74 of 107 rows are candidates. A consolidation pass could: merge duplicate candidates, cluster related claims, promote long-corroborated candidates, and compress clusters into one higher-trust row — always through the existing governed transitions, never by rewriting history.
Cost: **L**. Needs the LLM off the hot path (like today's semantic review) and a strict rule set so it cannot invent.

### Explicitly NOT planned
- A UI of any kind (owner decision, 2026-10-03).
- Multi-provider abstraction / plugin API (YAGNI — one provider is in use).
- Replacing SQLite.
